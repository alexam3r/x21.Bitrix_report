# Bitrix24 — отчёт по задачам сотрудников

Регулярный отчёт по эффективности сотрудников из задач Bitrix24 (облако) для
премирования и мотивации. Оркестрация — **n8n**, доставка — **в личку руководителю**
через `im.message.add`.

## Что считает

По каждому сотруднику за месяц/квартал (разрез «как исполнитель» и «с учётом соисполнения»):

- **Выполнено за период** — закрытые задачи (`CLOSED_DATE` в периоде);
- **К выполнению** — задачи с дедлайном в периоде (`DEADLINE`);
- **В срок** и **% выполнения**;
- **Просрочено** (= не выполнено) — красный флаг;
- **Без срока** — отдельной пометкой;
- **Учтённое время** (⏱) и **переносы дедлайнов** — из истории задач;
- **Возвраты на доработку** и **Кид** — коэффициент исполнительской дисциплины
  по Положению о доп. премировании (`Кид = Зсрок/Зплан − 0,3 × Звозв/Зплан`),
  с расчётной премией в % оклада.

Точные формулы — [docs/metrics.md](docs/metrics.md).

## Как устроено

```
n8n (расписание/вручную) → Set «Настройки» → Code «Собрать отчёт»
    → Bitrix REST: user.get + tasks.task.list ×2 + elapseditem + history (пагинация)
    → агрегация → текст отчёта + Кид
    → IF (dryRun = false?) → HTTP Request: im.message.add в личку руководителю
                           → Send Email: HTML-отчёт на почту (выключена, вкл. после настройки SMTP)
```

Логика вынесена в тестируемые модули `code/*.js`; тело Code-ноды n8n **собирается**
из них скриптом (единый источник правды).

| Файл | Назначение |
|---|---|
| `code/period.js` | границы отчётного периода (месяц/квартал/произвольный) |
| `code/aggregate.js` | раскладка задач по сотрудникам и метрики |
| `code/report.js` | формирование текста отчёта |
| `code/collect.js` | сбор данных из Bitrix (пагинация, история задач) |
| `scripts/build-workflow.mjs` | сборка `workflow/bitrix-report.n8n.json` |
| `scripts/smoke-workflow.mjs` | прогон тела Code-ноды без n8n |

## Команды

```bash
npm test               # юнит- и интеграционные тесты (node --test)
npm run build:workflow # пересобрать workflow из code/*.js
node scripts/smoke-workflow.mjs  # smoke-прогон собранной ноды
```

## Установка

См. [docs/setup.md](docs/setup.md): вебхук с правами `task`/`user`/`im`, `DIALOG_ID`
руководителя, импорт workflow, dry-run, расписание.

## Статус

- **Фаза 1**: базовые метрики + просрочки + доставка в личку. Готово.
- **Фаза 2**: время на задачи, переносы дедлайнов, email-резерв. Готово.
- **Фаза 3**: Кид и расчётная премия по Положению о доп. премировании;
  отправка вынесена в отдельные ноды (HTTP Request / Send Email за IF-гейтом). Готово.
