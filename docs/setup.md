# Установка и запуск

Пошаговая настройка отчёта по задачам Bitrix24 в n8n.

## 0. Предпосылки

- Развёрнутый **n8n** (у вас уже есть).
- Аккаунт Bitrix24 с правами **администратора** — вебхук наследует его видимость,
  а `tasks.task.list` показывает все задачи компании только администратору.

## 1. Создать входящий вебхук в Bitrix24

1. Профиль → **Приложения** (или **Разработчикам**) → **Другое** → **Входящий вебхук**.
2. Права (scope) задаются в секции **«Настройка прав»** → **`+ выбрать`** —
   выбор **множественный**. Отметить **три** пункта:
   - **Задачи** (`task`)
   - **Пользователи** (`user`)
   - **Чат и уведомления / Мессенджер** (`im`)

   > ⚠️ Не путать с секцией **«Генератор запросов» → Метод** — это тестовая
   > песочница для одного пробного вызова, к правам она отношения не имеет и всегда
   > держит один метод. Права — только в «Настройка прав». Если оставить её пустой,
   > запросы вернут `insufficient_scope`.
3. Нажать **«Создать»** и скопировать URL вида:
   `https://ВАШ_ПОРТАЛ.bitrix24.ru/rest/1/xxxxxxxxxxxx/`
   Здесь `1` — ID пользователя-владельца вебхука, `xxxx…` — токен.

> Базовый URL для настроек — **без завершающего слэша**:
> `https://ВАШ_ПОРТАЛ.bitrix24.ru/rest/1/xxxxxxxxxxxx`

## 2. Узнать DIALOG_ID руководителя

`DIALOG_ID` личной переписки = **ID пользователя** в Bitrix24. Открыть профиль
руководителя — в URL будет `/company/personal/user/ID/`. Это число и есть `managerDialogId`.

## 3. Импортировать workflow

1. В n8n: **Workflows → Import from File**.
2. Выбрать `workflow/bitrix-report.n8n.json`.

## 4. Заполнить настройки

Открыть **обе** ноды настроек — «Настройки: месяц» и «Настройки: квартал» — и в каждой
задать одинаковые значения:

| Поле | Значение |
|---|---|
| `webhookBaseUrl` | базовый URL из шага 1 (без слэша на конце) |
| `managerDialogId` | ID руководителя из шага 2 |
| `timezoneOffset` | смещение портала, напр. `+03:00` |
| `mode` | уже задан: `month` / `quarter` — не менять |
| `dryRun` | **оставить `true`** для первого прогона |
| `collectTime` | `true` — собирать учтённое время (`task.elapseditem.getlist`); `false` — отключить |
| `collectDeadlineShifts` | `true` — считать переносы дедлайнов И возвраты на доработку из истории задач (возвраты нужны для Кид); `false` — отключить |
| `maxHistoryTasks` | лимит запросов истории за прогон (по умолчанию 300; 1 запрос ≈ 1 задача с дедлайном в периоде) |

## 5. Проверить (dry-run, без отправки)

1. Нажать **Execute Workflow** (ветка «Запуск вручную»).
2. Открыть выход ноды **«Собрать отчёт»** → поле `message`.
3. Сверить цифры по 2–3 сотрудникам вручную в Битриксе (кол-во закрытых за месяц и
   просроченных) с отчётом. При `dryRun=true` IF-нода «Отправлять?» останавливает
   поток — ни личка, ни email не отправляются.

## 6. Включить отправку

Отправка — отдельные ноды после расчёта: IF-гейт по `dryRun`, за ним **«В личку
Bitrix (im.message.add)»** (HTTP Request) и **«Отчёт на email (SMTP)»**
(выключена по умолчанию, см. раздел про email).

1. В обеих нодах настроек выставить `dryRun` = **`false`**.
2. Снова **Execute Workflow** → сообщение придёт в личку руководителю.

**Как убедиться в доставке:** открыть выход ноды «В личку Bitrix» — в поле
`result` будет ID сообщения, который вернул `im.message.add`. Число там =
Битрикс принял и создал сообщение. Ошибка отправки видна прямо на этой ноде.

> ⚠️ Битрикс запрещает отправку сообщения самому себе: `managerDialogId` не
> должен совпадать с ID владельца вебхука (число в URL `/rest/ЧИСЛО/токен`),
> иначе будет «Вы не можете отправлять сообщения указанному получателю».

## 7. Включить расписание

Активировать workflow (тумблер **Active**). Триггеры:
- **Ежемесячно** — 1-го числа 06:00, отчёт за прошлый месяц.
- **Ежеквартально** — 1 января/апреля/июля/октября 07:00, за прошлый квартал.

Время — по часовому поясу сервера n8n; при необходимости скорректировать cron в
нодах расписания.

## Эксплуатация и правки

- **Изменить логику расчёта** — правьте `code/*.js`, затем:
  ```bash
  npm test && npm run build:workflow
  ```
  и переимпортируйте обновлённый `workflow/bitrix-report.n8n.json`. Тело Code-ноды
  собирается из `code/*.js` — вручную JSON не редактировать.
- **Проверить сборку без n8n:** `node scripts/smoke-workflow.mjs`.

## Замечания и ограничения

- **Лимиты API Bitrix24** — ~2 запроса/сек. n8n шлёт последовательно, для одной
  компании в месяц объём небольшой; при очень большом числе задач добавьте паузы.
- **Секрет.** `webhookBaseUrl` содержит токен — не публиковать, не коммитить с
  реальным значением (в артефакте — плейсхолдер).
- **Статусы задач.** «Выполнена» = `STATUS 5`. Если на портале кастомные статусы —
  поправьте `STATUS.DONE` в `code/aggregate.js`. Подробности — `docs/metrics.md`.
- **Задачи без дедлайна** не входят в `%`, показываются отдельной пометкой «без срока».

## Резервный канал: отчёт на email

Нода **«Отчёт на email (SMTP)»** уже есть в workflow (шлёт `messageHtml`
HTML-таблицей, тема — из `period.label`), но **выключена**: SMTP-креденшелы
n8n в JSON-экспорт не кладёт, а включённая нода без креденшелов валила бы
каждый прогон. Чтобы включить после импорта:

1. Открыть ноду, выбрать (или создать) **SMTP-креденшелы**.
2. Заполнить **From Email** и **To Email**.
3. Включить ноду (снять Disabled).

Email стоит за тем же IF-гейтом, что и личка: при `dryRun=true` письмо не
уходит. При повторном импорте обновлённого JSON выбор креденшелов и адреса
придётся заполнить заново.

## Замечания фазы 2

- **Время** появится в отчёте только если на портале используется учёт времени
  в задачах (кнопка «старт/стоп» или ручное время). Нули — это не ошибка.
- **Переносы дедлайнов и возвраты** — по одному запросу истории на задачу
  объединённой выборки (закрытые в периоде + с дедлайном в периоде). При вашем
  объёме (~230 задач/мес) прогон займёт ~2–3 минуты из-за лимитов API. Поле
  `historySkipped` в выходе ноды показывает, сколько задач не проверено из-за
  лимита `maxHistoryTasks` (0 — проверены все).

## Кид и премия (фаза 3)

В строке каждого сотрудника отчёт показывает **Кид** (коэффициент
исполнительской дисциплины по «Положению о доп. премировании», п. 4.3) и
расчётную премию в процентах оклада: `Кид 0.77 → премия 7.7%`. Формулы и
ограничения автоматики (согласование переносов, основания «Кид = 0» из п. 6.1)
— в `docs/metrics.md`. Итоговое значение по п. 5.1 Положения утверждает
руководитель — отчёт даёт расчётную основу.
